# API-контракт: Календарь звонков

Версия: 1.0

## Артефакты проекта

- `docs/api-contract.md` — человекочитаемый контракт (этот документ);
- `main.tsp` — TypeSpec-спецификация (машинное описание API), находится в корне проекта.

TypeSpec-спецификация — источник истины для API: она компилируется в OpenAPI.

Запуск компиляции (требует Node.js ≥ 20 и установленных пакетов):

```
npm install --save-dev @typespec/compiler @typespec/http @typespec/openapi3
npx tsp compile main.tsp --emit @typespec/openapi3
```

Результат — `tsp-output/@typespec/openapi3/openapi.yaml`.

## Общие положения

- **Транспорт**: REST over HTTP, обмен JSON (`application/json`).
- **Авторизация**: отсутствует. Роли разделяются только пространством URL:
  - общие endpoints — `/event-types`;
  - гость — `/guest/*`;
  - владелец календаря — `/admin/*` (единственный предзаданный профиль).
- **Время**: даты — `YYYY-MM-DD`, время — `HH:MM`. Полные моменты времени — ISO 8601 (`2026-08-18T08:00:00`) в локальном часовом поясе владельца (сервера). Конвертация в часовой пояс гостя не предусмотрена.
- **Окно записи**: доступны слоты на 14 календарных дней от текущей даты включительно — `[сегодня, сегодня+13]`.
- **Рабочее окно**: `08:00–20:00`, сетка с шагом 30 минут. Встреча `[startsAt, startsAt + duration]` должна целиком попадать в рабочее окно.
- **Статус слота**: только `free` | `booked`, одинаков для гостя и владельца.

## Модели данных

### EventType — тип события (метка события)

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | да | уникальный идентификатор, задаёт владелец, ≤ 50 симв. |
| `name` | string | да | название, ≤ 100 симв. |
| `description` | string | нет | описание, ≤ 1000 симв. |
| `duration` | int | да | длительность в минутах, кратно 30 (30, 60, 90, …) |

### Slot — слот (вычисляется, не хранится)

| Поле | Тип | Описание |
|---|---|---|
| `startsAt` | datetime | начало 30-минутной ячейки сетки |
| `status` | enum | `free` \| `booked` |

### Booking — бронирование

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | int | — | присваивается сервером |
| `eventTypeId` | string | да | id типа события (уникальная строка владельца) |
| `guestName` | string | да | имя гостя, ≤ 100 симв. |
| `guestContact` | string | да | контакт (email/телефон/telegram и т.п.), ≤ 200 симв. |
| `startsAt` | datetime | да | начало встречи |
| `endsAt` | datetime | — | вычисляется = `startsAt + duration` |

## Эндпоинты

### Общие (гость и владелец)

**`GET /event-types`** — список типов событий (имя, описание, длительность).

```
200 → [
  { "id": "consultation", "name": "Консультация", "description": "Разбор проекта", "duration": 30 }
]
```

### Гость

**`GET /guest/:date/?eventType=:id`** — слоты за день для выбранного типа события. Даты вне окна 14 дней недопустимы. Ответ `404`, если тип события не найден или дата вне окна.

```
200 → {
  "date": "2026-08-18",
  "eventType": { "id": "consultation", "name": "Консультация", "description": "Разбор проекта", "duration": 30 },
  "slots": [
    { "startsAt": "2026-08-18T08:00", "status": "free" },
    { "startsAt": "2026-08-18T08:30", "status": "booked" },
    { "startsAt": "2026-08-18T09:00", "status": "free" }
  ]
}
```

**`POST /guest/:date/availability`** — проверка доступности слота без создания брони.

```
Body: { "time": "08:00", "eventTypeId": "consultation" }
```

Ответы:
- `200` — `{ "available": true }` либо `{ "available": false, "reason": "booked" | "out-of-window" | "out-of-hours" | "invalid-grid" | "already-passed" }`;
- `404` — тип события не найден.

**`POST /guest/:date/booking`** — создать бронирование.

```
Body: { "time": "08:00", "eventTypeId": "consultation", "guestName": "Иван", "guestContact": "ivan@mail.ru" }
```

Ответы:
- `201` — объект Booking:
  ```
  { "id": 12, "eventTypeId": "consultation", "eventTypeName": "Консультация", "duration": 30,
    "guestName": "Иван", "guestContact": "ivan@mail.ru",
    "startsAt": "2026-08-18T08:00:00", "endsAt": "2026-08-18T08:30:00" }
  ```
- `404` — тип события не найден;
- `409` — `{ "error": "Slot is already booked" }` (слот занят);
- `422` — ошибки валидации (см. правила);
- `400` — `{ "error": "Invalid request" }` (битые данные, неверный формат).

### Владелец

**`POST /admin/event-types`** — создать тип события.

```
Body: { "id": "consultation", "name": "Консультация", "description": "Разбор проекта", "duration": 30 }
```

Ответы:
- `201` — объект EventType;
- `409` — `{ "error": "Event type with this id already exists" }` (id уже занят);
- `422` — ошибки валидации.

**`GET /admin/:date/`** — все слоты за день, все типы событий и брони без фильтра. Ответ `404`, если дата вне окна 14 дней.

```
200 → {
  "date": "2026-08-18",
  "slots": [
    { "startsAt": "2026-08-18T08:00", "status": "free" },
    { "startsAt": "2026-08-18T08:30", "status": "booked",
      "booking": { "id": 12, "eventType": { "id": "consultation", "name": "Разбор", "duration": 30 },
                   "guestName": "Иван", "guestContact": "ivan@mail.ru" } }
  ]
}
```

**`GET /admin/`** — страница встреч: все брони всех типов событий одним списком, начиная с начала сегодняшнего дня (включая уже прошедшие сегодня), сортировка по возрастанию.

```
200 → { "bookings": [
  { "id": 12, "eventType": { "id": "consultation", "name": "Консультация", "duration": 30 },
    "guestName": "Иван", "guestContact": "ivan@mail.ru",
    "startsAt": "2026-08-18T08:00:00", "endsAt": "2026-08-18T08:30:00" }
] }
```

## Правила

### Валидация при создании типа события

1. Поля `id`, `name`, `duration` обязательны и непусты → `422`.
2. `id` — уникальная строка, ≤ 50 симв.; повторное использование id → `409`.
3. `duration` — положительное число, кратное 30 → `422`.

### Валидация при создании брони (в порядке проверки)

1. Тип события `eventTypeId` существует → иначе `404`.
2. Поля `time`, `eventTypeId`, `guestName`, `guestContact` обязательны и непусты → `422`.
3. Дата в пути внутри окна `[сегодня, сегодня+13]` → иначе `422`.
4. `time` имеет формат `HH:MM` и попадает на границу сетки (кратно 30 мин) → `422`.
5. Встреча `[startsAt, startsAt + duration]` целиком в рабочем окне `08:00–20:00` того же дня → `422`.
6. `startsAt` ещё не наступил → `422`.
7. Интервал не пересекается ни с одной существующей бронью (любого типа) → иначе `409`.

### Занятость

Два бронирования конфликтуют при пересечении интервалов независимо от типа события:
`existing.startsAt < newEnd && newStart < existing.endsAt`.
Проверка выполняется на сервере + ограничение уникальности на уровне БД (защита от гонок).

### Окно записи

Доступные слоты формируются на 14 дней от текущей даты. Слоты с уже наступившим временем не предлагаются.

## Формат ошибок

- `404` — `{ "error": "Event type not found" }` (или «Date is out of booking window»);
- `409` — `{ "error": "Slot is already booked" }` либо `{ "error": "Event type with this id already exists" }`;
- `422` — `{ "errors": [ { "field": "guestName", "message": "..." } ] }`;
- `400` — `{ "error": "Invalid request" }` (битые данные, неверный формат).
