# Пользовательские сценарии

Основные сценарии для проверки сервиса «Календарь звонков». Интеграционные
сценарии помечены меткой e2e — они покрыты Playwright-тестами в
`frontend/e2e/booking.spec.ts` и гоняются против реального стека (фронт + FastAPI-бэк).

Рабочее окно бронирования: 08:00–20:00, шаг сетки 30 минут, окно записи 14 дней
от текущей даты включительно.

## S1. Гость бронирует свободный слот (happy path) — e2e

1. Гость открывает главную страницу `/`.
2. Видит список типов событий; первый тип выбран автоматически.
3. На календаре выбирает будущий день (в пределах окна 14 дней).
4. В списке «Свободные слоты» нажимает на свободный слот.
5. В модальном окне вводит имя и контакт, нажимает «Забронировать».
6. Появляется экран «Забронировано!» с кодом брони и временем.

**Ожидаемый результат:** бронь создана на бэке (`POST /guest/:date/booking` → 201),
слот помечается занятым для последующих посетителей.

## S2. Повторное бронирование занятого слота — e2e

1. Слот уже занят бронью (см. S1).
2. Отправляется повторная попытка брони того же слота.

**Ожидаемый результат:** бэк возвращает `409 { "error": "Slot is already booked" }`,
фронт показывает сообщение «Слот уже занят», бронь не создаётся.

## S3. Владелец создаёт тип события — e2e

1. Владелец открывает `/admin/event-types/new`.
2. Заполняет ID, название, длительность (кратна 30) и, при желании, описание.
3. Нажимает «Создать».

**Ожидаемый результат:** тип события создан (`POST /admin/event-types` → 201),
владелец возвращается на дашборд; тип события виден на странице «Типы событий»
и доступен гостям для бронирования.

## S4. Владелец видит встречи и слоты дня — e2e

1. Владелец открывает `/admin` — дашборд «Встречи» (все встречи начиная с сегодняшнего дня,
   включая уже прошедшие сегодня).
2. Видит созданные брони (время, тип события, длительность, гость, контакт),
   отсортированные по времени начала.
3. Открывает `/admin/day` и выбирает день — видит все слоты дня со статусом
   «Свободно» / «Занято» и данными гостя у занятых.

**Ожидаемый результат:** данные совпадают с бронью, созданной в S1.

## S5. Гость повторно открывает день после брони — e2e

1. После успешной брони (S1) гость снова открывает тот же день и тип события.
2. Занятый слот исчезает из «Свободных слотов» и появляется в секции «Занятые».

**Ожидаемый результат:** исключена возможность «двойного» бронирования глазами гостя.
